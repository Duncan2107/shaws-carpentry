# SEO plan

Shaws Carpentry, shawscarpentry.com. Written 2026-08-15 from an audit of the
live site and the code.

Tick items off as they are done. Anything marked **[R]** is recurring: it has
to be revisited whenever content is added or changed, and the trigger is
listed in [Recurring work](#recurring-work) at the bottom.

## How to read the priorities

For a local carpenter the order of what actually wins work is:

1. Google Business Profile and the map pack
2. Real photographs of real jobs
3. Genuine reviews
4. A page for each service, naming the towns served
5. Everything technical

The technical items are still worth doing, they are cheap and they stop the
site tripping over itself. They will not on their own move it up the results.

## Tier 1: technical foundations

Fast, all developer work, no input needed from Stuart except item 8.

- [x] **1. Sitemap and robots.txt.** Done, in `src/sitemap.js`. Both are
      generated by the Worker. The sitemap's `lastmod` for each page is worked
      out from the tables that actually feed that page, so it stays truthful on
      its own. Neither file names the domain, both take it from the request,
      so the next client site inherits them working. Still to do once
      deployed: confirm Cloudflare's managed block sits above ours in
      `robots.txt`, and submit the sitemap in Search Console as part of item 8.
- [x] **2. Canonical tags.** Done, in `src/meta.js`. Generated from the
      normalised path, so the address is the same however the request was
      written.
- [x] **3. Open Graph and Twitter card tags.** Done, in `src/meta.js`. Built
      from what each page already says: the title and description are read back
      out of the page's own head, the locale from `<html lang>`, the business
      name from the `business_name` setting and the address from the request.
      A page declares one thing for itself, its share picture:
      `<meta property="og:image" content="/Media/decking.jpg">` written
      root-relative. Still to do once deployed: run the four pages through
      Facebook's Sharing Debugger, which is also how a card gets refreshed if
      the picture is changed later.
- [x] **4. Business structured data.** Done, in `src/schema.js`. Typed
      `HomeAndConstructionBusiness`, read from the `settings` table, and
      repeated on all four pages under one fixed `@id` so the four pages read
      as one business rather than four. **Two deliberate omissions:** no postal
      address, because publishing where somebody works is Stuart's decision and
      not a side effect of an SEO change, and no opening hours, because the
      settings hold prose he can edit freely and anything parsing it would be
      one edit away from publishing hours the business does not keep. Both are
      one key away if he wants them.
- [x] **5. Service structured data.** Done. One node per service, from the same
      rows that render the cards, so adding a service in the admin adds its
      markup with no code change.
- [x] **6. BreadcrumbList.** Done, on the three inner pages. Two levels today;
      it earns its keep properly once item 9 gives each service a page and the
      trail reads Home, Services, Fitted Kitchens.
- [x] **7. A real 404 page.** Done, `public/404.html`, served by the Worker so
      the footer's contact details come from the database like everywhere else.
      Carries `noindex`, and no canonical, Open Graph or structured data, since
      it stands for no particular address. `/404` and `/404.html` answer 404
      themselves rather than 200, so the page cannot be indexed as a page that
      exists. A missing image or script gets a plain 404 without a database
      read, so a bot walking random addresses cannot run up queries.
- [ ] **8. Search Console and Bing Webmaster Tools.** **[R]** Duncan already
      manages Search Console for the domain and has access, so no verification
      record is needed. What is left, once deployed: submit `/sitemap.xml`,
      then check coverage. Bing Webmaster Tools can import straight from Search
      Console. Needs checking monthly once it is running.

## Tier 2: content and structure

This is where ranking actually comes from. Items 9 and 11 are substantial
projects, not afternoon jobs.

- [ ] **9. A page for each service.** **[R]** Sixteen services currently share
      one page, each with a two-line card. Nobody searches "carpentry
      services", they search "fitted wardrobes Tunbridge Wells". Each service
      needs its own URL, 300 to 600 words, its own photographs and its own
      questions and answers. Needs a schema migration for a `slug` column, a
      route in the Worker, a template in `src/content.js` and a body-copy field
      in the admin. Every service added afterwards needs the same treatment.
- [ ] **10. Name the towns.** "Sussex and Kent" appears everywhere and no
      actual town does. Decide the real travel radius with Stuart and name the
      places: Haywards Heath, Crawley, Tunbridge Wells, East Grinstead, or
      whichever they genuinely are.
- [ ] **11. Area pages.** One page per main town. Effective, but only worth
      doing once the service pages exist, and only with genuinely different
      copy on each. Thin duplicated location pages do more harm than good.
- [ ] **12. Fill the gallery.** **[R]** Stuart's job, and it may be worth more
      than items 1 to 8 combined. Real project photographs with descriptive
      captions are indexable content, image-search traffic, and the thing that
      turns a visitor into an enquiry. Ongoing, not a one-off.
- [ ] **13. Publish reviews**, then add AggregateRating structured data once
      there are several genuine ones. **[R]** Google expects reviews to be
      collected first-party or pulled from a profile, so this pairs with item
      15.
- [ ] **14. Questions and answers** on the contact or services page with
      FAQPage structured data. Cheap, and it can win the answer box for things
      like "how much does a fitted wardrobe cost".

## Tier 3: off-site

Stuart's to do, and it outranks everything in the other tiers.

- [ ] **15. Google Business Profile.** **[R]** For a local carpenter the map
      pack sits above the organic results. Nothing on the website beats this.
      Needs verification, categories, service areas and photographs, then a
      habit of asking every finished customer for a review. Ongoing forever.
- [ ] **16. Bing Places**, same details.
- [ ] **17. Directory listings** with identical name, phone and address
      everywhere: Checkatrade, Which? Trusted Traders, the Guild of Master
      Craftsmen, Yell, Facebook, Instagram. **[R]** Consistency is the signal,
      so any change to the phone number or email has to be pushed to all of
      them.
- [ ] **18. Decide on the name collision.** Several other Shaw and Shaws
      carpentry firms exist and one has a very similar domain. Worth knowing
      before spending anything on brand-term visibility.

## Tier 4: performance and Core Web Vitals

- [ ] **19. WebP with responsive srcset.** **[R]** The hero images are 300 to
      370KB JPEGs and the hero is the largest element on every page. Large
      improvement for modest effort. Note that the admin uploader currently
      shrinks photos to 1600px JPEG in the browser, so uploads made through the
      admin will keep arriving as JPEG unless the uploader is changed too.
      Changing the uploader is what stops this recurring.
- [ ] **20. Width and height on every image.** **[R]** Only the logo has them,
      so everything else can shift the layout as it loads, which is a
      penalty. Any image added later needs them too.
- [ ] **21. Self-host the two Google fonts.** Currently a render-blocking
      third-party request on every page load. Also removes a third-party call
      from the privacy picture.
- [ ] **22. Short edge cache on the HTML** instead of `no-cache`, using
      `s-maxage` with `stale-while-revalidate` so edits still appear quickly.

## Tier 5: make it repeatable for the next client site

- [ ] **23. SEO fields in the admin:** per-page title, meta description and
      share image, so Stuart can edit them without touching code and the next
      client site inherits the same panel. This is what turns items 3 and 8
      from developer jobs into something the client owns.
- [ ] **24. Add `form_endpoint` to the Contact details tab.** Already flagged
      as a known gap in `CLAUDE.md`. Worth doing while in that screen.

## Recurring work

The principle: **anything generated from the database never recurs, anything
hand-written does.** That is why items 1, 4 and 5 are specified as generated.
Build them the other way and they join this list.

### Triggered by adding a new page

| Trigger | What has to be done |
|---|---|
| A new page of any kind | Title and meta description written for it (item 23 makes this a form field rather than a code change) |
| A new page of any kind | One `og:image` line in its head naming its share picture. The canonical tag and the rest of the Open Graph tags follow automatically from items 2 and 3, so this single line is all that is left |
| A new page of any kind | Breadcrumb markup |
| A new page of any kind | Linked to from somewhere sensible in the navigation, footer or body copy. An unlinked page is close to invisible |
| A new page of any kind | Sitemap entry. Automatic if item 1 is built from the database |

### Triggered by adding a service in the admin

| Trigger | What has to be done |
|---|---|
| New service row | Its own service page written, once item 9 exists. A service with no page is a dead end for anyone searching for it |
| New service row | Service structured data. Automatic, item 5 reads the same rows |
| New service row | Added to the enquiry form dropdown. Already automatic, it follows `show_on_services` |

### Triggered by adding photographs

| Trigger | What has to be done |
|---|---|
| New gallery project | A caption that describes the work and, where it is true, the town. "Fitted oak wardrobes, Haywards Heath" earns its place, "Job 14" does not |
| New gallery project | Alt text on every image, which the admin already prompts for |
| New gallery project | Converted to WebP, unless item 19 also changes the uploader |
| New gallery project | Width and height present on the rendered markup, per item 20 |

### Triggered by changing contact details

| Trigger | What has to be done |
|---|---|
| Phone, email, hours or areas changed in the admin | The website updates itself, including the structured data if item 4 is built from settings |
| Phone, email, hours or areas changed in the admin | Google Business Profile updated by hand |
| Phone, email, hours or areas changed in the admin | Every directory listing from item 17 updated by hand. Inconsistent details across listings actively damage local ranking |

### Standing routines, no trigger

| How often | What |
|---|---|
| Monthly | Search Console: check coverage, look at which queries are bringing people in, look for pages that dropped out of the index |
| Monthly | Add photographs and a short post to the Google Business Profile. A profile that goes quiet slides down the map pack |
| After every finished job | Ask the customer for a Google review, then publish the good ones to the website |
| Quarterly | Re-run a page-speed check after any batch of new photographs, since images are what regresses |
| Quarterly | Confirm the sitemap still lists everything and nothing 404s |
